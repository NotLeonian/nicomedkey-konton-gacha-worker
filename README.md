# Nicomedkey Konton Gacha Worker

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/NotLeonian/nicomedkey-konton-gacha-worker)

[nicomedkey.cc](https://nicomedkey.cc/) の混沌ぼっと（`@konton_freedom`）の混沌ガチャを自動で引く Cloudflare Worker です。

## できること

この Worker を有効にすると、`@konton_freedom 混沌ガチャ` を 2 時間ごとに自動で投稿します。
投稿時刻の目安は、日本時間の 00:01、02:01、04:01、…です。

混沌ぼっとからの返信に記載された現在のポイントが 3,600 以上なら、`@konton_freedom プレミアムポイントガチャ10連` を投稿します。
以降も 10 連の結果が届くたびに現在のポイントを確認し、3,600 未満になるまで 10 連を繰り返します。

## 必要なもの

- Cloudflare アカウント
- nicomedkey.cc アカウント
- nicomedkey.cc API トークン

API トークンには、`ノートを作成・削除する`（`write:notes`）の権限だけを付与してください。

## デプロイ

ページ上部の `Deploy to Cloudflare` ボタンを押してください。

Cloudflare のセットアップ画面で、次の手順に沿って設定します。

1. Cloudflare と GitHub をまだ接続していない場合は、「新しい GitHub 接続」から接続します。
2. 「プライベート Git リポジトリを作成する」にチェックを入れます（必須ではありませんが、推奨します）。
3. `NICOMEDKEY_TOKEN` に API トークンを入力します。
4. 自動投稿を有効にする場合は、`ENABLED` を `true` にします。
5. 「非本番ブランチのビルド」のチェックを外します（必須ではありませんが、推奨します）。
6. `Deploy` をクリックします。

D1 データベースは自動的に作成されます。

## 重複投稿を防ぐ仕組み

通常ガチャは、日本時間を基準に 2 時間ごとに区切った各時間帯に 1 回だけ投稿します。
投稿履歴を D1 データベースに保存しているため、同じ時間帯に繰り返し投稿されることはありません。

また、混沌ぼっとから届いた返信 1 件につき、次のプレミアムポイントガチャは 1 回だけ投稿します。

ネットワーク障害などで投稿結果を確認できない場合は、重複投稿を避けるため、自動では再送しません。
その記録は `manual_review` 状態になるため、投稿済みかどうかを手動で確認してください。

10 連の返信から残高を確認できない場合も、次の 10 連は投稿しません。
この場合も記録は `manual_review` 状態になるため、返信の内容を手動で確認してください。

## 設定と投稿記録を確認する

デプロイ後、次の URL を開いてください。

https://YOUR-WORKER.workers.dev/health

`enabled` では自動投稿が有効かどうかを、`runs` では状態ごとの記録件数を確認できます。
`manualReview` は、`manual_review` 状態になっている記録の件数です。
値が 1 以上なら、該当する投稿や返信を手動で確認してください。

## 注意事項

### 利用制限と利用規約

このプログラムは、混沌ぼっとが設けている「2 時間に 1 回」という制限を回避するものではありません。
混沌ぼっとから次に引ける時刻を案内された場合も、その時間帯には再投稿せず、次の予定時刻を待ちます。

[nicomedkey.cc](https://nicomedkey.cc/) または混沌ぼっとの利用規約や運用方針が変更された場合は、変更後の内容に従い、必要に応じてこの Worker を停止してください。

### 初回のデプロイでビルドに失敗した場合

初回のデプロイでは、`package.json` がプライベートリポジトリにコピーされる前にビルドが始まり、失敗することがあります。
ビルドが `cloudflare[bot]` による `source repo import` より前のコミットを参照している場合は、`source repo import` の完了後にプライベートリポジトリへ空のコミットをプッシュするなどして、再度ビルドしてください。

なお、ビルドに失敗しても、すでに Worker が稼働している場合は、その Worker を削除する必要はありません。
